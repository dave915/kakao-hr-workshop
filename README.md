# 일상 밖으로 · 카카오뱅크 HR 워크샵

카카오뱅크 인사팀을 위한 모바일 PWA. 지도는 카카오맵 Web SDK를 사용합니다. 개인 입장 링크, 일정, 추진위원회 공지와 푸시, GPS 보물찾기를 한 앱에 담았습니다. React + TypeScript + Vite로 만든 정적 화면은 **GitHub Pages**, 인증·데이터·푸시는 **Firebase**를 사용합니다.

## 바로 실행

Node.js 22 이상이 필요합니다.

```sh
npm ci
npm ci --prefix functions
npm run dev -- --host 127.0.0.1 --port 4187 --strictPort
```

`http://127.0.0.1:4187`에서 확인합니다. Firebase 설정이 없는 개발 환경은 **예시 데이터로 실행**됩니다. 우측 상단에 미리보기 표시가 있으며, 나의 탐험 여권에서 슈퍼 어드민 / 참가자 역할을 전환할 수 있습니다. 예시 코드와 게임 기록은 현재 브라우저에만 저장됩니다.

```sh
npm run build:demo
npm run preview -- --host 127.0.0.1 --port 4188 --strictPort
```

실제 배포 빌드 `npm run build`는 Firebase가 없을 때 참가자 또는 관리자로 자동 로그인하지 않습니다. GitHub Pages 워크플로는 Firebase 및 카카오맵 설정이 없으면 배포를 중단합니다.

## 구현된 기능

- 참가자 이름은 회사 아이디의 첫 번째 점 앞 영어 이름을 사용합니다. `dave.h` → `Dave`, `dans.jeong` → `Dans`. 홈은 `안녕하세요 Dave!`로 인사하며 프로필·팀·개인 순위·발견 기록·공지 작성자에도 같은 규칙을 적용합니다.
- 개인별 192비트 난수 코드와 `#/join/코드` 입장 링크. 서버는 코드의 SHA-256 해시로 로그인 요청을 검증하고 Firebase Custom Token으로 본인을 식별합니다. 반복 복사를 위한 링크 원문은 서버 전용 저장소에 별도로 보관하며 슈퍼 어드민 전용 API로만 조회합니다. 로그인 후 URL에서 코드를 제거합니다.
- `dave.h`를 초기 슈퍼 어드민으로 생성하는 운영자 도구. 슈퍼 어드민은 다른 참가자를 추진위원회로 지정하거나 해제할 수 있습니다.
- 참가자 추가, 팀 지정, 입장 여부, 개인 링크 재발급. 재발급 즉시 기존 링크와 세션 버전은 무효화됩니다.
- 슈퍼 어드민의 `전체 대원 참가링크 복사`: 검색 필터와 관계없이 영문명·참가링크 두 열을 엑셀에 바로 붙여넣습니다. 반복 복사해도 링크가 유지되고 기존 링크·로그인이 끊기지 않습니다.
- 대원 정보는 영문명·아이디로 표시하며, 한 명 추가 시 아이디·팀만 입력합니다. `명단 붙여넣기`에서 영문명·팀명 2열을 복사해 최대 100명을 한 번에 등록합니다. 기존 3열 명단도 지원하며, 중복·누락 미리보기, 전체 원자적 저장, 개인 링크 일괄 복사·파일 저장을 제공합니다. [참가자 관리 안내](docs/participant-management.md)
- 참가자 목록에서 앱 설치 확인·삭제 추정·최근 접속·푸시 등록 기기 수와 기기별 상태를 확인합니다. 기기 상태는 관리자만 볼 수 있고, 설치 해제는 지원 브라우저에 다시 접속했을 때 감지할 수 있습니다.
- 소식 화면에서 확인한 공지는 읽음 처리해 종 배지를 지웁니다. ‘미배정’과 ‘워추위’ 팀은 팀순위에서 제외합니다.
- 참가자 관리의 `계정 관리 → 삭제`에서 개별 삭제. 프로필·점수·팀 기여도와 모든 입장 링크·기기 등록을 함께 제거해 기존 로그인 접근도 차단합니다. 슈퍼 어드민과 현재 로그인한 본인은 삭제할 수 없으며, 추진위원회 계정은 슈퍼 어드민만 삭제할 수 있습니다. 이미 찾은 보물·꽝은 발견 완료로 유지하고 발견자는 `삭제된 참가자`로 표시합니다.
- 날짜별 일정, 다음 여정, 한국 시간 기준 진행 상태, 일정 추가·수정·삭제.
- 전체 / 팀 대상 공지 및 FCM 푸시 발송, 발송 결과 기록, 기기별 알림 등록·해제. 앱을 보고 있을 때도 시스템 알림을 표시합니다. 나의 탐험 여권에서 실제 알림 권한·기기 구독 상태를 확인하고 `알림 다시 연결하기`로 재등록할 수 있습니다. 긴 공지는 푸시에서 요약 길이로 잘리고 앱에는 전체가 남습니다.
- 관리자 공지 삭제. 이미 전송된 푸시는 회수되지 않습니다.
- 이미 발견된 보물도 삭제 가능. 해당 발견 기록과 지급 점수를 취소해 개인·팀 순위에 반영하며, 꽝 삭제 시 그 꽝으로 생긴 휴식 제한도 해제합니다.
- 슈퍼 어드민 전용 전체 초기화: 워크샵 설정에서 `모두 초기화하기`를 누르고 `전체 초기화`를 입력하면 공지·보물·꽝·일정·팀·점수·발견·휴식 기록을 지우고 기본 설정으로 돌아갑니다. 슈퍼 어드민을 제외한 참가자와 추진위원회, 이들의 입장 링크와 기기 알림 등록을 삭제합니다. 슈퍼 어드민의 계정·입장 링크·알림 설정은 유지하고 팀은 미배정으로 바꿉니다.
- 보물 배치에 두 등록 모드: **현장에서 등록**은 현재 GPS 위치를 확인해 `저장하고 다음`, **지도에서 배치**는 여러 핀을 놓고 끌어서 조정한 뒤 초안을 한 번에 저장합니다.
- 자동 이름, 복제, 포인트·반경 설정 재사용. 좌표는 상세 설정에서 직접 입력할 수도 있습니다. 작성 중 초안·선택·지도 배율은 같은 계정의 이 브라우저에 보관되고, 전체 초기화하면 이전 초안은 복구하지 않습니다.
- 일괄 저장은 전체를 검증한 뒤 한 트랜잭션으로 처리합니다. 발견된 보물 수정, 다른 관리자가 수정·삭제한 원본 덮어쓰기, 100개 초과를 차단하며 실패한 초안은 유지합니다. [등록 사용법과 검증](docs/treasure-registration.md)
- 서버의 거리·위치 정확도·최신 위치 검증. Firestore 트랜잭션으로 **선착순 한 명만 발견**합니다.
- 참가자 지도는 발견 완료 보물과 내 위치만 표시합니다. 미발견 보물은 힌트 목록에서 선택하고 큰 지도 탐색 모드에서 찾습니다.
- 보물찾기 화면에 들어오면 현재 위치를 자동으로 확인해 지도 중심을 이동합니다. 위치 권한이 필요하며, 실패하면 안내 후 `내 위치로 이동` 버튼으로 다시 시도할 수 있습니다.
- 큰 지도에서는 보물 힌트를 고르기 전에도 내 위치가 실시간 갱신됩니다. 방향 권한을 허용하면 위치 점의 화살표와 하단 힌트 영역에 내 방향·보물 방향을 함께 표시합니다. 약 20° 이내로 맞으면 초록색과 체크 표시로 ‘방향이 맞아요’를 알려줍니다. 지도는 북쪽을 위로 유지하며, 직접 움직이면 따라가기를 멈추고 `내 위치로`를 누르면 다시 따라갑니다. 확대 수준은 GPS·방향 갱신 중에도 유지됩니다.
- 지도 탐색은 새 GPS 위치가 확인될 때마다 서버에 8방위 방향, 약 10m 단위 거리와 탐험 온도를 요청합니다. 5초 대기 없이 갱신하고, 응답을 기다리는 동안 들어온 위치는 가장 최신 것만 이어서 처리합니다. 내 방향과 일치 여부는 휴대폰 방향 센서에 즉시 반응합니다. 지도 위쪽이 북쪽이며 실제 도로 경로 안내는 아닙니다.
- 큰 지도 하단의 나침반 힌트를 누르면 방향을 크게 볼 수 있습니다. 휴대폰 기준 화살표, 대략적인 거리, 방향 일치 강조와 발견 범위 안내를 표시하고 지도 보기로 돌아오면 기존 지도를 유지합니다.
- 가까워짐·멀어짐 변화 표시, GPS 정확도가 낮거나 오래된 경우 안내 중지, 탐색 종료 시 위치 추적 해제.
- 발견한 보물은 실시간 X 표시, 개인·팀 순위 및 팀 보물 수첩.
- 꽝은 서버 시간으로 5분간 **보물찾기만** 잠금. 일정과 공지는 계속 열립니다.
- GPS·나침반 기반 위치 AR. 힌트를 선택하고 `카메라 AR로 찾기`를 누르면 가까운 보물의 실제 좌표를 기준으로 카메라 방향·기울기·이동에 맞춰 보물 상자가 표시됩니다. 화면 밖에는 회전 안내가 나오고, 발견 반경 안에서는 상자를 눌러 획득합니다.
- 보물·꽝 획득에는 카메라가 필수입니다. 지도에서는 `카메라 켜고 획득하기`로 AR 화면을 열고, 실제 카메라 영상이 재생 중일 때만 획득할 수 있습니다. 지도와 미리보기의 바로 획득 버튼은 제공하지 않습니다. 카메라가 중지·일시 정지되거나 영상이 없으면 획득을 차단합니다.
- AR 시작 시 카메라·위치·방향 권한 요청, GPS 오차 표시, 부정확하거나 오래된 위치·방향에서 표시와 획득 중지. AR 닫기·획득·앱을 배경으로 전환할 때 카메라·센서·GPS 감시를 해제합니다. 카메라 영상은 저장하거나 전송하지 않습니다.
- PWA 설치, 업데이트 안내, 앱 리소스 캐시, Firestore의 이전 조회 데이터 오프라인 캐시. 보물 발견과 관리자 변경은 온라인 서버 연결이 필요합니다. 지도 타일은 미리 내려받거나 대량 캐시하지 않습니다.

## 사진 게시판

하단 **사진첩**에서 사진 1~3장과 글을 올리고 세로 피드로 볼 수 있습니다. 게시글·댓글 하트와 500자 이내의 댓글·답글을 지원합니다. 피드에는 원댓글 아래 답글을 묶어 최대 3줄로 보여주며, 댓글은 작성자와 추진위원회가 삭제할 수 있습니다. 본인과 추진위원회가 삭제할 수 있으며, 사진은 자동 압축해 비공개 미국 서부 Firebase Storage에 보관합니다. 개인별 업로드 제한 없이 전체 월 1,000장·전체 보관 4,000장 한도를 적용합니다. [사진첩 운영·비용·권한 안내](docs/photo-board.md)

## 처음 배포하기

운영 주소: **https://dave915.github.io/kakao-hr-workshop/**

Firebase 프로젝트: `kakao-hr-workshop-915` (서울 리전). GitHub Pages와 Firebase Functions / Firestore / Authentication / FCM 설정을 완료했습니다. 개인 입장 링크가 없는 사용자는 로그인 화면만 볼 수 있습니다. 재배포와 계정 복구는 [배포 절차](docs/deployment.md)를 참고하세요.

1. GitHub 저장소와 Firebase 프로젝트를 만듭니다.
2. Firebase Authentication, Firestore, Cloud Messaging을 설정합니다.
3. Functions와 Firestore 보안 규칙을 배포합니다.
4. 신뢰할 수 있는 운영자 환경에서 `dave.h`의 초기 링크를 발급합니다.
5. GitHub 저장소 변수에 Firebase Web 설정을 등록하고 GitHub Pages를 Actions 소스로 활성화합니다.
6. 실제 휴대폰에서 초대 링크, 보물찾기와 푸시를 확인합니다.

Firebase Cloud Functions를 실제로 배포하려면 Blaze 요금제 설정이 필요합니다. [Firebase 공식 배포 안내](https://firebase.google.com/docs/functions/get-started)

## 검증

```sh
npm run check          # 게임/권한 테스트 + 프런트엔드/Functions 타입 검사와 빌드
npm run test:rules     # Firestore Emulator로 실제 보안 규칙 검증
npm run test:backend   # Auth + Firestore + Functions Emulator로 통합 검증
```

에뮬레이터는 Java 21 이상을 사용합니다. 로컬 포트는 Firestore 8387, Functions 5387, Auth 9387, UI 4387입니다. 테스트는 `demo-workshop` 프로젝트로만 실행하며 실제 Firebase에 데이터를 쓰지 않습니다. [검증 결과](docs/verification.md)

## 운영 설계와 범위

- 원본 워크샵 상태는 관리자 전용 `workshops/main`에, 참가자에게 공개할 상태는 `workshops/participants`에 같은 트랜잭션으로 저장합니다. 미발견 보물의 좌표와 종류는 참가자 문서에 포함하지 않습니다. 이번 규모의 행사를 위한 구조이며 코드상 참가자 500명, 보물 100개, 일정 100개, 최근 공지 100개를 제한합니다. 대규모·상시 운영 전에는 컬렉션 분리와 부하 검증이 필요합니다.
- 지도 탐색 안내는 인증된 서버가 계산하고 대략적인 방향·거리만 반환합니다. AR에서는 선택한 미발견 보물이 `max(100m, 발견 반경 + 40m)` 안에 있고 GPS 오차가 40m 이하일 때만 해당 보물의 좌표를 일시적으로 제공합니다. 전체 미발견 좌표와 꽝 종류는 공개하지 않으며 AR 좌표는 브라우저 저장소나 참가자 상태 문서에 저장하지 않습니다. 위치를 반복 조회하면 목표를 좁혀갈 수 있고, 이동 경로는 별도로 저장하지 않습니다.
- 위치 AR은 GPS·절대 방향 센서로 좌표를 카메라 영상에 투영하는 방식입니다. 바닥 인식·영상 추적·가림 처리·실제 고도 측정은 없으며 평지와 약 1.3m의 카메라 높이를 가정합니다. GPS·자기장·기기별 카메라 화각에 따라 표시 오차가 있습니다. 실제 휴대폰에서 현장 보정을 확인하고, 방향 센서를 지원하지 않거나 권한이 거부된 환경에서는 지도 탐색을 이용하세요. [AR 구현·검증 범위](docs/ar.md)
- 참가자 신원·점수·역할·게임 상태는 서버에서만 변경합니다. 클라이언트의 직접 쓰기는 관리자도 차단됩니다.
- 참가자 개별 삭제와 전체 초기화는 상태·인증 프로필·입장 링크·기기 등록을 같은 Firestore 트랜잭션에서 변경하므로 삭제된 계정은 기존 로그인 토큰으로도 접근할 수 없습니다. Firebase Authentication의 내부 UID 레코드와 운영 감사 기록·로그인 시도 제한은 남지만, 삭제된 UID로 워크샵에 재입장할 수는 없습니다. 실제 운영 데이터 삭제·초기화는 관리 화면의 명시적 실행으로만 이뤄집니다.
- 꽝 종류, 입장 코드 해시, 기기 토큰, 감사 기록은 별도 비공개 문서에 저장됩니다. 관리자만 꽝 종류를 읽을 수 있습니다.
- 정상 입장은 동일한 워크샵 Wi-Fi를 사용해도 로그인 실패 횟수 제한에 포함되지 않습니다. 실패한 시도만 IP 해시 단위로 제한합니다.
- 개인 링크는 해당 계정의 로그인 수단입니다. 실제 링크나 서비스 계정 파일을 저장소, 이슈, CI 로그에 올리지 마세요. 자신의 링크 재발급은 화면에서 막고 운영자 복구 도구로 수행합니다.
- 팀 공지는 수신 화면과 푸시 대상을 구분하는 기능입니다. 모든 참가자가 읽는 워크샵 상태 문서에 들어 있으므로 비밀 공지 용도로 쓰면 안 됩니다.
- GPS는 기기가 제공하는 좌표이므로 위조 위치까지 막는 수단은 아닙니다. 사내 친목 행사 용도를 기준으로 합니다.
- FCM 접수 수는 기기 표시나 읽음 수가 아닙니다. 네트워크 장애로 발송 도중 함수가 중단되면 공지에 `처리 중`이 남을 수 있으며 로그 확인이 필요합니다. 현재 자동 재전송 큐는 없습니다.
- 브라우저 캐시에는 해당 기기에서 읽은 워크샵 데이터가 남을 수 있습니다. 개인 기기를 사용하고 공용 기기는 브라우저 사이트 데이터를 지워주세요.
