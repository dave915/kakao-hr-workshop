# 일상 밖으로 · 카카오뱅크 HR 워크샵

카카오뱅크 인사팀을 위한 모바일 PWA. 지도는 카카오맵 Web SDK를 사용합니다. 개인 입장 링크, 일정, 추진위원회 공지와 푸시, GPS 보물찾기를 한 앱에 담았습니다. React + TypeScript + Vite로 만든 정적 화면은 **GitHub Pages**, 인증·데이터·푸시는 **Firebase**를 사용합니다.

## 바로 실행

Node.js 22 이상이 필요합니다.

```sh
npm ci
npm ci --prefix functions
npm run dev -- --host 127.0.0.1 --port 4187 --strictPort
```

`http://127.0.0.1:4187`에서 확인합니다. Firebase 설정이 없는 개발 환경은 **예시 데이터로 실행**됩니다. 우측 상단에 미리보기 표시가 있으며, 나의 탐험 여권에서 슈퍼 어드민 / 참가자 역할을 전환할 수 있습니다. 예시 코드와 게임 기록은 현재 브라우저에만 저장됩니다.

```sh
npm run build:demo
npm run preview -- --host 127.0.0.1 --port 4188 --strictPort
```

실제 배포 빌드 `npm run build`는 Firebase가 없을 때 참가자 또는 관리자로 자동 로그인하지 않습니다. GitHub Pages 워크플로는 Firebase 및 카카오맵 설정이 없으면 배포를 중단합니다.

## 구현된 기능

- 개인별 192비트 난수 코드와 `#/join/코드` 입장 링크. 서버는 코드의 SHA-256 해시만 저장하고 Firebase Custom Token으로 본인을 식별합니다. 로그인 후 URL에서 코드를 제거합니다.
- `dave.h`를 초기 슈퍼 어드민으로 생성하는 운영자 도구. 슈퍼 어드민은 다른 참가자를 추진위원회로 지정하거나 해제할 수 있습니다.
- 참가자 추가, 팀 지정, 입장 여부, 개인 링크 재발급. 재발급 즉시 기존 링크와 세션 버전은 무효화됩니다.
- 날짜별 일정, 다음 여정, 한국 시간 기준 진행 상태, 일정 추가·수정·삭제.
- 전체 / 팀 대상 공지 및 FCM 푸시 발송, 발송 결과 기록, 기기별 알림 등록·해제. 긴 공지는 푸시에서 요약 길이로 잘리고 앱에는 전체가 남습니다.
- 카카오맵에서 보물과 꽝 배치, 힌트·포인트·발견 반경 설정, 현재 위치로 지도 이동.
- 서버의 거리·위치 정확도·최신 위치 검증. Firestore 트랜잭션으로 **선착순 한 명만 발견**합니다.
- 참가자 지도는 발견 완료 보물과 내 위치만 표시합니다. 미발견 보물은 힌트 목록에서 선택하고 큰 지도 탐색 모드에서 찾습니다.
- 탐색 시작 시 GPS를 추적하고 약 5초 간격으로 서버가 8방위 방향, 약 10m 단위 거리와 탐험 온도를 안내합니다. 지도 위쪽이 북쪽이며 실제 도로 경로 안내는 아닙니다.
- 가까워짐·멀어짐 변화 표시, GPS 정확도가 낮거나 오래된 경우 안내 중지, 탐색 종료 시 위치 추적 해제.
- 발견한 보물은 실시간 X 표시, 개인·팀 순위 및 팀 보물 수첩.
- 꽝은 서버 시간으로 5분간 **보물찾기만** 잠금. 일정과 공지는 계속 열립니다.
- 카메라 위 보물 이미지 연출. 공간에 고정되는 AR / 영상 인식 기능은 아닙니다.
- PWA 설치, 업데이트 안내, 앱 리소스 캐시, Firestore의 이전 조회 데이터 오프라인 캐시. 보물 발견과 관리자 변경은 온라인 서버 연결이 필요합니다. 지도 타일은 미리 내려받거나 대량 캐시하지 않습니다.

## 처음 배포하기

운영 주소: **https://dave915.github.io/kakao-hr-workshop/**

Firebase 프로젝트: `kakao-hr-workshop-915` (서울 리전). GitHub Pages와 Firebase Functions / Firestore / Authentication / FCM 설정을 완료했습니다. 개인 입장 링크가 없는 사용자는 로그인 화면만 볼 수 있습니다. 재배포와 계정 복구는 [배포 절차](docs/deployment.md)를 참고하세요.

1. GitHub 저장소와 Firebase 프로젝트를 만듭니다.
2. Firebase Authentication, Firestore, Cloud Messaging을 설정합니다.
3. Functions와 Firestore 보안 규칙을 배포합니다.
4. 신뢰할 수 있는 운영자 환경에서 `dave.h`의 초기 링크를 발급합니다.
5. GitHub 저장소 변수에 Firebase Web 설정을 등록하고 GitHub Pages를 Actions 소스로 활성화합니다.
6. 실제 휴대폰에서 초대 링크, 보물찾기와 푸시를 확인합니다.

Firebase Cloud Functions를 실제로 배포하려면 Blaze 요금제 설정이 필요합니다. [Firebase 공식 배포 안내](https://firebase.google.com/docs/functions/get-started)

## 검증

```sh
npm run check          # 게임/권한 테스트 + 프런트엔드/Functions 타입 검사와 빌드
npm run test:rules     # Firestore Emulator로 실제 보안 규칙 검증
npm run test:backend   # Auth + Firestore + Functions Emulator로 통합 검증
```

에뮬레이터는 Java 21 이상을 사용합니다. 로컬 포트는 Firestore 8387, Functions 5387, Auth 9387, UI 4387입니다. 테스트는 `demo-workshop` 프로젝트로만 실행하며 실제 Firebase에 데이터를 쓰지 않습니다. [검증 결과](docs/verification.md)

## 운영 설계와 범위

- 원본 워크샵 상태는 관리자 전용 `workshops/main`에, 참가자에게 공개할 상태는 `workshops/participants`에 같은 트랜잭션으로 저장합니다. 미발견 보물의 좌표와 종류는 참가자 문서에 포함하지 않습니다. 이번 규모의 행사를 위한 구조이며 코드상 참가자 500명, 보물 100개, 일정 100개, 최근 공지 100개를 제한합니다. 대규모·상시 운영 전에는 컬렉션 분리와 부하 검증이 필요합니다.
- 탐색 안내는 인증된 서버가 계산하고 정확한 목표 좌표는 반환하지 않습니다. 방향과 거리는 게임 진행에 필요한 대략적인 값이며 반복 탐색으로 위치를 좁혀갈 수 있습니다. 이동 경로를 별도로 저장하지 않습니다.
- 참가자 신원·점수·역할·게임 상태는 서버에서만 변경합니다. 클라이언트의 직접 쓰기는 관리자도 차단됩니다.
- 꽝 종류, 입장 코드 해시, 기기 토큰, 감사 기록은 별도 비공개 문서에 저장됩니다. 관리자만 꽝 종류를 읽을 수 있습니다.
- 정상 입장은 동일한 워크샵 Wi-Fi를 사용해도 로그인 실패 횟수 제한에 포함되지 않습니다. 실패한 시도만 IP 해시 단위로 제한합니다.
- 개인 링크는 해당 계정의 로그인 수단입니다. 실제 링크나 서비스 계정 파일을 저장소, 이슈, CI 로그에 올리지 마세요. 자신의 링크 재발급은 화면에서 막고 운영자 복구 도구로 수행합니다.
- 팀 공지는 수신 화면과 푸시 대상을 구분하는 기능입니다. 모든 참가자가 읽는 워크샵 상태 문서에 들어 있으므로 비밀 공지 용도로 쓰면 안 됩니다.
- GPS는 기기가 제공하는 좌표이므로 위조 위치까지 막는 수단은 아닙니다. 사내 친목 행사 용도를 기준으로 합니다.
- FCM 접수 수는 기기 표시나 읽음 수가 아닙니다. 네트워크 장애로 발송 도중 함수가 중단되면 공지에 `처리 중`이 남을 수 있으며 로그 확인이 필요합니다. 현재 자동 재전송 큐는 없습니다.
- 브라우저 캐시에는 해당 기기에서 읽은 워크샵 데이터가 남을 수 있습니다. 개인 기기를 사용하고 공용 기기는 브라우저 사이트 데이터를 지워주세요.
