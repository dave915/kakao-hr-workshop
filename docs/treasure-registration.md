# 보물 등록

현장 등록은 `보물 놓기 → 보물 선택 → 등록` 순서로 진행합니다. 남은 금액별 수량을 먼저 확인하고, 금액을 선택하면 GPS를 가져와 위치 확인 화면을 엽니다. 지도 일괄 배치와 기존 보물 수정은 `지도에서 배치 · 등록한 보물 관리`에서 사용합니다.

## 사용법

- **현장에서 등록:** 숨길 장소에서 `보물 놓기`를 누르고 금액 또는 꽝을 고릅니다. GPS 오차와 핀을 확인한 다음 `이 위치에 등록`을 누릅니다. 이름은 자동 입력되며 힌트는 선택 사항입니다. 위치는 가져온 좌표로 고정되며 이동 중 저절로 바뀌지 않습니다. `현재 위치 다시 확인`이나 지도 클릭·핀 이동으로 조정할 수 있습니다. 위치 권한을 거부했거나 지도 로딩에 실패하면 접힌 상세 입력에서 좌표를 직접 입력할 수 있습니다.
- **남은 보물:** 등록된 보물을 기준으로 금액별 남은 개수와 전체 남은 금액을 표시합니다. 초안 선택·취소·실패는 차감하지 않으며, 발견 완료 보물은 계속 등록 수량에 포함합니다. 등록 삭제 시 해당 금액의 수량이 돌아옵니다. 같은 화면을 연 다른 관리자의 등록도 실시간 데이터에 반영됩니다.
- **기존 보물:** 금액이 없던 보물은 `금액 미지정`으로 표시하고 재고에서 제외합니다. `기존 보물 금액 지정하기`에서 미발견 보물을 수정해 금액을 지정할 수 있습니다. 기존 금액이나 게임 포인트를 추측해 자동 배정하지 않습니다. 전체 등록 제한은 금액 미지정 보물을 포함해 100개입니다.
- **지도에서 배치:** 상세 관리의 `핀 추가` 상태에서 여러 장소를 누릅니다. 각 초안에서 이름·금액을 확인하고, 노란 핀을 끌어 위치를 바꿉니다. 힌트는 필요할 때만 입력합니다. `초안 N개 모두 저장`으로 함께 등록합니다. 새 핀을 놓거나 저장할 때 지도 중심과 배율을 유지합니다.
- **힌트 없이 찾기:** 참가자는 보물 목록에서 이름으로 선택하고 나침반의 방향·거리 안내를 따라 탐색합니다. 힌트가 없으면 빈 문단을 표시하지 않으며, 입력한 힌트는 기존처럼 표시합니다. 힌트는 최대 300자이고, 빈 값·공백·생략된 값은 서버에서 빈 문자열로 저장합니다.
- **복제:** 초안 또는 등록된 보물의 복제 버튼을 누르면 새 ID로 이름·힌트·종류·좌표·설정을 복사합니다. 지도에서 새 위치를 지정할 수 있습니다. 발견한 보물도 복제할 수 있지만 원본 발견 기록은 변경하지 않습니다.
- **상세 설정:** 포인트(10~~1,000), 발견 반경(10~~200m, 기본 10m), 위도·경도를 조정합니다. 꽝을 선택하면 포인트 입력이 숨겨집니다. GPS를 사용할 수 없으면 지도 또는 `좌표로 입력`으로 등록합니다. 기존 브라우저에 남은 기본값 50m는 10m로 전환하며, 저장된 보물과 작성 중인 초안의 반경은 유지합니다.
- **초안:** 수정할 때마다 이 브라우저에 보관합니다. 계정·프로젝트·전체 초기화 세대별로 분리하며, 참가자에게는 저장 전 초안이 공개되지 않습니다. 초안의 휴지통 버튼은 확인 후 입력을 버립니다. 다른 기기와 초안은 동기화하지 않습니다.

## 저장 규칙

기본 구성은 50,000원×1, 30,000원×2, 20,000원×5, 10,000원×10, 5,000원×20, 2,000원×33, 1,000원×24, 꽝×5로 총 500,000원·100개입니다. 금액은 `prizeAmount`에 기록하며 게임의 순위 포인트와 분리합니다. 빠른 등록은 기존 기본값 100P·반경 10m를 사용하고 상세 관리에서 조정할 수 있습니다. 꽝은 0원이며 기존 5분 휴식 규칙을 유지합니다.

금액과 꽝 여부는 발견 전 참가자 문서에서 제외합니다. 발견 후에는 발견 결과와 기록에 금액을 표시합니다. 단건·일괄 저장 모두 최종 상태의 금액별 한도를 검증하며 Firestore 트랜잭션 안에서 처리하므로 마지막 수량에 동시 등록해도 초과할 수 없습니다. 응답 유실 후 동일 ID 재시도는 이중 차감하지 않습니다. 이미 지정한 금액을 이전 클라이언트가 누락해 덮어쓰는 요청은 거부합니다.

`saveTreasures`는 서버에서 권한과 모든 입력을 검증합니다. 전체 보물은 최대 100개이며 중복 ID를 거부합니다. 원본 수정 시 함께 보낸 스냅샷을 현재 값과 비교하여 다른 관리자의 수정·삭제를 덮어쓰지 않습니다. 발견된 보물은 수정할 수 없습니다. 성공한 저장을 응답 유실로 재시도해도 발견 기록을 초기화하지 않습니다.

한 항목이라도 충돌하면 원본 상태·참가자 뷰·비공개 종류에 일부만 반영하지 않습니다. 전체 초기화 세대가 바뀌면 이전 화면에서 진행 중이던 저장도 거부합니다. 이전 클라이언트의 단건 `saveTreasure`는 호환성을 위해 유지합니다.

## 금액별 현장 등록 검증 — 2026-10-01

- 단위 테스트 132개와 앱·서버 빌드 통과. 정확히 100개·500,000원 등록, 금액별 한도 초과의 무변경, 단건 저장의 동일 제한, 재시도 시 이중 차감 방지, 금액 교환·삭제에 따른 재고 복원, 기존 보물 금액 지정·초안 복원, 발견 전 비공개·발견 후 금액 반환을 확인했습니다.
- Firebase 통합 테스트 21개 통과. 서로 다른 두 ID가 마지막 50,000원 보물을 동시에 등록할 때 한 요청만 성공하며, 참가자 문서에 금액이 노출되지 않고 성공 요청 재시도에도 보물 수가 유지됨을 확인했습니다.
- 모바일 390×844·데스크톱 1440×1000 로컬 데모 확인: 세 단계 등록, 모의 GPS로 빈 힌트 등록, 저장 후 99개·450,000원 표시와 50,000원 선택 차단, 위치 권한 거부 시 등록 차단, 새로고침 후 초안 복원, 취소 시 재고 유지, 기존 보물 금액 지정 시 전체 개수 유지, 화면 가로 넘침·런타임 오류 없음. 실제 야외 GPS 정확도는 모의 검증 범위에 포함하지 않습니다.
