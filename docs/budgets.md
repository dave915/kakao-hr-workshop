# 워크샵 예산

모바일 전체 메뉴 또는 데스크톱 사이드바의 **워크샵 예산**에서 이용합니다. 기존 하단 탭 다섯 개는 유지합니다.

1. 워추위(추진위원회·슈퍼 어드민)가 **예산 추가**에서 이름과 원화 금액을 등록합니다.
2. 예산 목록에서 항목을 누르면 해당 예산의 지출 내역이 열립니다.
3. 상세 화면 맨 위에서 손가락으로 아래로 당겼다가 놓으면 지출 입력창이 열립니다. 짧은 당김·가로 이동·여러 손가락·취소된 터치는 등록창을 열지 않습니다. 스크롤 중에는 일반 스크롤을 유지합니다. **지출 등록** 버튼으로도 같은 창을 열 수 있습니다.
4. 모든 참가자가 내용·금액·유형·지출일·선택 메모를 입력합니다. 유형은 식비·간식 / 교통 / 숙박 / 활동 / 물품 / 기타입니다.
5. 지출은 **확인 대기**로 저장합니다. 워추위가 **확정**을 누르면 확정자와 상태가 표시됩니다. 작성자는 로그인 계정으로 자동 기록하며, 목록과 입력창에 `dave.h`처럼 점 뒤까지 포함한 전체 아이디로 표시합니다.
6. 워추위는 예산 목록의 **삭제**에서 예산 금액과 포함된 지출 건수·합계를 확인한 뒤 예산을 삭제할 수 있습니다. 확정 지출을 포함한 해당 예산의 모든 지출도 함께 삭제됩니다.

## 권한과 계산

| 작업 | 일반 참가자 | 워추위 |
| --- | --- | --- |
| 예산·지출 조회 | 가능 | 가능 |
| 예산 추가 | 불가 | 가능 |
| 예산·포함된 지출 전체 삭제 | 불가 | 삭제 확인 후 가능 |
| 지출 등록 | 가능 | 가능 |
| 확인 대기 지출 수정·삭제 | 본인 작성분 | 모든 지출 |
| 지출 확정·확정 취소 | 불가 | 가능 |

확정 지출은 수정·삭제할 수 없습니다. 수정이 필요하면 워추위가 확정을 취소한 뒤 변경하고 다시 확정합니다. 다른 사람이 변경하거나 확정한 지출을 오래된 화면에서 덮어쓰는 요청은 거절합니다. 다른 계정의 권한을 팀 이름으로 추정하지 않습니다.

예산 전체 삭제는 위 개별 지출 삭제와 별도 동작입니다. 삭제 확인창을 연 뒤 누군가 지출을 추가·수정·확정·삭제하면 서버가 전체 삭제를 거절합니다. 창을 닫고 최신 내역을 확인한 뒤 다시 삭제해야 합니다. 이미 삭제한 예산의 재요청은 중복 처리하지 않습니다.

당기기는 손가락에 맞춰 화면과 안내를 이동시키고, 충분히 당겨 놓으면 약 160ms 동안 열림 안내를 보여준 뒤 입력창을 450ms에 걸쳐 올립니다. 취소한 당김은 300ms 동안 제자리로 돌아옵니다. 버튼으로 등록해도 같은 입력창 전환을 사용하며, 동작 줄이기 설정에서는 자동 이동과 대기 시간을 제거합니다.

**남은 예산 = 예산 − 확정 지출 − 확인 대기 지출**입니다. 대기 비용도 이미 쓴 비용이므로 반영하며 확정 시 이중 차감하지 않습니다. 예산을 초과해도 실제 지출을 등록할 수 있고, 초과 금액을 표시합니다. 작성자·확정자 아이디와 당시 회사 아이디를 보존해 계정 삭제 후에도 기록을 식별합니다.

## 저장과 운영

- 기존 `workshopAction` Firebase callable과 트랜잭션을 사용합니다. `workshops/main.budgets`와 참가자용 `workshops/participants.budgets`에 같은 예산 정보를 저장하므로 모든 참가자가 지출 내용·금액·작성자를 볼 수 있습니다. 직접 Firestore 쓰기는 기존 규칙으로 차단합니다.
- 기존 문서에 `budgets`가 없어도 빈 목록으로 처리합니다. 운영 예산 예시는 자동 생성하지 않습니다.
- 생성 요청의 UUID로 재시도 중복을 방지합니다. 지출 변경은 revision을 확인하고 확정·수정 경합 중 한 요청만 반영합니다. 작성자, 확정자, 시각, 상태는 서버에서 결정합니다.
- 금액은 1원~10억 원의 정수, 예산 50개, 워크샵 전체 지출 500건, 메모 300자까지 지원합니다. Firestore 문서 한도에 여유를 두고 직렬화한 전체 상태가 900,000바이트를 넘는 예산 변경은 저장 전에 거절합니다.
- **전체 초기화**는 예산과 지출도 지웁니다. 초기화 이전 화면의 저장 요청은 세대 번호로 차단합니다.
- 미리보기는 기존 로컬 저장소를 사용합니다. 운영 화면에서는 온라인 Firebase 연결이 필요합니다.
- 배포 시 프런트엔드와 Firebase Functions를 함께 갱신해야 합니다. 보안 규칙이나 인덱스 변경은 필요하지 않습니다.

## 검증

- `tests/budgets.test.ts`: 참가자 등록·워추위 확정, 작성자 위조 차단, 중복 생성, 수정·확정 충돌, 확정 잠금·취소, 잘못된 금액·날짜, 계정 삭제, 전체 초기화, 예산 초과, 저장 용량.
- `tests/backend.emulator.test.ts`: 실제 callable 인증·권한, Firestore 참가자 문서 반영, 동시 등록 중복 방지, 수정·확정 경합.
- `npm run check`, `npm run test:backend`와 모바일 브라우저에서 상세 화면 당기기·버튼 등록·뒤로 가기·확정 흐름을 확인합니다.

2026-11-05 검증: 기본 테스트 270개, Auth·Firestore·Functions 에뮬레이터 통합 테스트 28개, 프런트엔드와 Functions 빌드가 통과했습니다. 에뮬레이터는 로컬 JDK 23으로 실행했습니다. Chromium의 터치 이벤트로 당겨서 등록, 짧은 당김·가로 이동·취소 방지를 확인했고, 참가자 등록 → 워추위 확정 → 확정 취소 → 수정 → 재확정과 대기 지출 삭제를 확인했습니다. 예산 전체 삭제의 권한·변경 감지·연결 지출 제거, 입력창의 450ms 전환과 열림 전 뒤로 가기·동작 줄이기도 검증했습니다. 320·390·768·1440px에서 가로 넘침이 없고, 새로고침 후 기록이 유지됐습니다. 실제 iPhone Safari와 Android 기기에서의 터치 검증은 별도로 필요합니다.

신규 예산 컴포넌트의 디자인 소스 검사에는 실패가 없습니다. 블러 경고가 가리킨 `backdrop-filter: none`은 공통 서랍의 블러를 제거하는 선언입니다. 전체 화면 자동 검사에서 지적한 기존 사이드바 장식 문자·10px 보조 글자, 하단 탐색 유리 그라데이션, 미리보기 배지 대비는 기존 디자인 시스템 범위로 유지했습니다.
