# 워크샵 예산

모바일 전체 메뉴 또는 데스크톱 사이드바의 **워크샵 예산**에서 이용합니다. 기존 하단 탭 다섯 개는 유지합니다.

1. 워추위(추진위원회·슈퍼 어드민)가 **예산 추가**에서 이름과 원화 금액을 등록합니다.
2. 예산 목록에서 항목을 누르면 해당 예산의 지출 내역이 열립니다.
3. 상세 화면 맨 위에서 손가락으로 아래로 당겼다가 놓으면 지출 입력창이 열립니다. 짧은 당김·가로 이동·여러 손가락·취소된 터치는 등록창을 열지 않습니다. 스크롤 중에는 일반 스크롤을 유지합니다. 별도의 `+ 지출 등록` 버튼은 제공하지 않습니다. 상단 당김 안내를 누르거나 키보드로 선택해도 같은 창을 열 수 있습니다. 팝업 하단의 `지출 등록하기` 저장 버튼은 유지합니다.
4. 모든 참가자가 내용·금액·유형·지출일과 선택 항목인 장소·메모를 입력합니다. 유형은 식비·간식 / 교통 / 숙박 / 활동 / 물품 / 기타입니다.
5. 지출은 **확인 대기**로 저장합니다. 워추위가 **확정**을 누르면 확정자와 상태가 표시됩니다. 작성자는 로그인 계정으로 자동 기록하며, 목록과 입력창에 `dave.h`처럼 점 뒤까지 포함한 전체 아이디로 표시합니다.
6. 예산과 지출 항목을 **왼쪽으로 밀면 수정·삭제**가 나타납니다. 오른쪽으로 밀거나 항목·바깥 영역을 누르면 닫힙니다. 바깥의 다른 버튼을 누르면 슬라이드를 닫으면서 해당 동작도 바로 실행합니다. `…` 메뉴와 키보드 왼쪽·오른쪽 방향키로도 열고 닫을 수 있습니다. 한 목록에서는 한 항목만 열립니다.
7. 워추위는 예산 이름·금액을 수정하거나, 포함된 지출 건수·합계를 확인한 뒤 예산을 삭제할 수 있습니다. 확정 지출을 포함한 해당 예산의 모든 지출도 함께 삭제됩니다. 지출은 본인 또는 워추위가 수정·삭제하며, 확정된 지출은 확정 취소 전까지 두 버튼이 비활성화됩니다.

## 사용내역 CSV 복사

예산 목록의 **사용내역 복사**는 모든 예산의 지출을 복사합니다. 개별 예산의 **사용내역 복사**는 현재 상태 필터(전체 / 확인 대기 / 확정)에 해당하는 지출만 복사합니다. 조회할 수 있는 참가자는 누구나 사용할 수 있으며, 복사할 내역이 없으면 버튼이 비활성화됩니다.

열 순서는 `결제일자,결제자,구분,타이틀,금액,장소,비고`입니다. 결제일자는 지출일(`YYYY-MM-DD`), 결제자는 작성자 전체 아이디(`dave.h`), 구분은 지출 유형, 타이틀은 지출 내용, 비고는 메모입니다. 금액은 통화 기호나 천 단위 쉼표 없는 원 단위 숫자입니다. 장소가 없거나 공백이면 정확히 `-`를 넣고, 비고가 없으면 빈칸으로 둡니다.

최신 지출일 순으로 복사하며 쉼표·따옴표·줄바꿈은 CSV 필드 규칙으로 보존합니다. 스프레드시트에서 수식으로 해석될 수 있는 사용자 텍스트에는 작은따옴표를 앞에 붙입니다. 클립보드 권한이 없으면 수동으로 전체 선택·복사할 수 있는 읽기 전용 창을 표시합니다. 기존 기록의 장소를 임의로 추정하지 않습니다.

## 권한과 계산

| 작업 | 일반 참가자 | 워추위 |
| --- | --- | --- |
| 예산·지출 조회 | 가능 | 가능 |
| 예산 추가 | 불가 | 가능 |
| 예산 이름·금액 수정 | 불가 | 가능 |
| 예산·포함된 지출 전체 삭제 | 불가 | 삭제 확인 후 가능 |
| 지출 등록 | 가능 | 가능 |
| 확인 대기 지출 수정·삭제 | 본인 작성분 | 모든 지출 |
| 지출 확정·확정 취소 | 불가 | 가능 |

확정 지출은 수정·삭제할 수 없습니다. 수정이 필요하면 워추위가 확정을 취소한 뒤 변경하고 다시 확정합니다. 다른 사람이 변경하거나 확정한 지출을 오래된 화면에서 덮어쓰는 요청은 거절합니다. 다른 계정의 권한을 팀 이름으로 추정하지 않습니다.

예산 전체 삭제는 위 개별 지출 삭제와 별도 동작입니다. 삭제 확인창을 연 뒤 누군가 예산을 수정하거나 지출을 추가·수정·확정·삭제하면 서버가 전체 삭제를 거절합니다. 창을 닫고 최신 내역을 확인한 뒤 다시 삭제해야 합니다. 이미 삭제한 예산의 재요청은 중복 처리하지 않습니다. 예산 수정도 버전을 비교하며 기존 지출과 작성자 기록을 유지합니다.

당기기는 손가락에 맞춰 화면과 안내를 이동시킵니다. 충분히 당겨 놓으면 별도 대기나 위치 초기화 없이 배경 복귀와 입력창의 450ms 전환을 함께 시작합니다. 취소한 당김은 300ms 동안 제자리로 돌아옵니다. 입력창은 화면 높이의 약 2/3이며, 닫기·등록 버튼은 고정하고 입력 영역만 세로로 스크롤합니다. 가로 스크롤과 스크롤 끝의 튕김은 차단하며, 날짜 입력과 좁은 화면의 열 너비도 컨테이너 안에 제한합니다. 키보드로 보이는 화면이 줄면 그 높이 안에 맞춥니다. 당김 안내를 눌러 열어도 같은 전환을 사용하고, 동작 줄이기 설정에서는 자동 이동을 제거합니다.

**남은 예산 = 예산 − 확정 지출 − 확인 대기 지출**입니다. 대기 비용도 이미 쓴 비용이므로 반영하며 확정 시 이중 차감하지 않습니다. 예산을 초과해도 실제 지출을 등록할 수 있고, 초과 금액을 표시합니다. 작성자·확정자 아이디와 당시 회사 아이디를 보존해 계정 삭제 후에도 기록을 식별합니다.

## 저장과 운영

- 기존 `workshopAction` Firebase callable과 트랜잭션을 사용합니다. `workshops/main.budgets`와 참가자용 `workshops/participants.budgets`에 같은 예산 정보를 저장하므로 모든 참가자가 지출 내용·금액·작성자를 볼 수 있습니다. 직접 Firestore 쓰기는 기존 규칙으로 차단합니다.
- 기존 문서에 `budgets`가 없어도 빈 목록으로 처리합니다. 운영 예산 예시는 자동 생성하지 않습니다.
- 생성 요청의 UUID로 재시도 중복을 방지합니다. 지출 변경은 revision을 확인하고 확정·수정 경합 중 한 요청만 반영합니다. 작성자, 확정자, 시각, 상태는 서버에서 결정합니다.
- 금액은 1원~10억 원의 정수, 예산 50개, 워크샵 전체 지출 500건, 장소 100자, 메모 300자까지 지원합니다. 장소 항목이 없는 예전 클라이언트의 수정 요청도 이미 저장된 장소를 지우지 않습니다. Firestore 문서 한도에 여유를 두고 직렬화한 전체 상태가 900,000바이트를 넘는 예산 변경은 저장 전에 거절합니다.
- **전체 초기화**는 예산과 지출도 지웁니다. 초기화 이전 화면의 저장 요청은 세대 번호로 차단합니다.
- 미리보기는 기존 로컬 저장소를 사용합니다. 운영 화면에서는 온라인 Firebase 연결이 필요합니다.
- 서버 액션을 변경한 배포에서는 프런트엔드와 Firebase Functions를 함께 갱신해야 합니다. 보안 규칙이나 인덱스 변경은 필요하지 않습니다.

## 검증

- `tests/budgets.test.ts`: 참가자 등록·워추위 확정, 작성자 위조 차단, 중복 생성, 수정·확정 충돌, 확정 잠금·취소, 잘못된 금액·날짜, 계정 삭제, 전체 초기화, 예산 초과, 저장 용량.
- `tests/backend.emulator.test.ts`: 실제 callable 인증·권한, Firestore 참가자 문서 반영, 동시 등록 중복 방지, 수정·확정 경합.
- `npm run check`, `npm run test:backend`와 모바일 브라우저에서 상세 화면 당기기·버튼 등록·뒤로 가기·확정 흐름을 확인합니다.

2026-11-05 검증: 기본 테스트 272개, Auth·Firestore·Functions 에뮬레이터 통합 테스트 28개, 프런트엔드와 Functions 빌드가 통과했습니다. 에뮬레이터는 로컬 JDK 23으로 실행했습니다. Chromium의 터치 이벤트로 당겨서 등록, 짧은 당김·가로 이동·취소 방지를 확인했고, 참가자 등록 → 워추위 확정 → 확정 취소 → 수정 → 재확정과 대기 지출 삭제를 확인했습니다. 예산 전체 삭제의 권한·변경 감지·연결 지출 제거, 놓는 순간의 프레임별 위치 연속성, 2/3 높이 입력창, 좌우 밀기로 수정·삭제 열기, 뒤로 가기·동작 줄이기도 검증했습니다. 320·390·768·1440px에서 가로 넘침이 없고, 새로고침 후 기록이 유지됐습니다. 실제 iPhone Safari와 Android 기기에서의 터치 검증은 별도로 필요합니다.

신규 예산 컴포넌트의 디자인 소스 검사에는 실패가 없습니다. 블러 경고가 가리킨 `backdrop-filter: none`은 공통 서랍의 블러를 제거하는 선언입니다. 전체 화면 자동 검사에서 지적한 기존 사이드바 장식 문자·10px 보조 글자, 하단 탐색 유리 그라데이션, 미리보기 배지 대비는 기존 디자인 시스템 범위로 유지했습니다.

사진 피드백 반영 검증: WebKit iPhone 15 에뮬레이션에서 슬라이드 배경색, 바깥 탭 닫기와 다른 버튼의 동작 유지, 날짜·메모 입력 후 내부 스크롤과 팝업 경계 고정을 확인했습니다. Chromium에서는 실제 브라우저 터치 입력으로 당김 안내에서 등록창을 여는 경로와 가로 드래그 차단을 확인했습니다. 물리적인 iPhone의 관성·키보드 동작은 기기에서 추가 확인이 필요합니다.

CSV 검증: `tests/budget-export.test.ts`에서 열 순서·전체 아이디·구분·숫자 금액·장소 누락의 `-` 처리·쉼표/따옴표/줄바꿈·최신순·수식 형태 텍스트를 확인했습니다. 기본 테스트 283개와 서버 통합 테스트 28개가 통과했습니다. Chrome에서는 실제 클립보드를 읽어 전체/상태별 CSV를 확인하고 권한 거부 시 수동 복사를 검증했으며, WebKit iPhone 모드에서도 탭으로 자동 복사가 완료됐습니다.
