# GPS·나침반 기반 위치 AR

## 사용 흐름

1. 보물찾기에서 미발견 힌트를 선택합니다.
2. `카메라 AR로 찾기` → `카메라·위치·방향 켜기`를 누르고 권한을 허용합니다.
3. 휴대폰을 세우고 주변을 비춥니다. 가까운 보물은 GPS 좌표 방향에 나타나며, 화면을 돌리거나 걸으면 표시 위치가 변합니다. 화면 밖의 목표에는 좌·우·상·하 회전 안내를 표시합니다.
4. 카메라 영상이 재생 중이고 발견 반경 안에 있을 때 보물 상자 또는 `카메라로 획득하기`를 누릅니다. 서버의 거리·잠금·선착순 검증을 거쳐 점수를 지급합니다. 지도에서 범위 안에 도착하면 `카메라 켜고 획득하기`로 이동하며 지도에서 바로 획득할 수는 없습니다.
5. `지도에서 이어가기`로 카메라를 닫고 지도 탐색을 계속할 수 있습니다.

## 구현

- `shared/ar.ts`: 동·북·상 좌표계를 기기의 Z-X'-Y'' 회전 행렬과 후면 카메라 방향으로 변환합니다. 화면 회전과 카메라 영상의 `object-fit: cover` 잘림을 보정해 목표를 화면에 투영합니다. [W3C 방향 센서 회전 행렬](https://www.w3.org/TR/orientation-event/#worked-example)
- `useDevicePose`: Android의 절대 방향 이벤트와 Safari의 `webkitCompassHeading`을 사용합니다. 북쪽 기준이 없는 상대 alpha 값은 위치 AR에 쓰지 않습니다. iOS의 동작·방향 권한 요청은 시작 버튼의 사용자 동작 안에서 호출합니다. [방향 권한 요청](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static)
- `getArTarget`: 로그인·세션 버전·멤버 상태·게임 진행·미발견·잠금 검증. GPS가 20초 이내, 오차 40m 이하이고 선택한 보물이 `max(100m, 발견 반경 + 40m)` 이내일 때만 해당 좌표를 반환합니다. 멀리 있으면 지도와 같은 대략적인 안내만 반환합니다.
- AR 조회는 서버 데이터를 변경하지 않습니다. 미발견 지도 좌표는 계속 숨기며, AR 조회로 받은 좌표는 메모리에만 유지합니다. 꽝 정체는 발견 전까지 공개하지 않습니다.
- 지도 탐색은 새 GPS 위치마다 서버 방향 안내를 갱신하고, 요청 중 새 위치가 도착하면 최신 위치만 이어서 처리합니다. AR의 근거리 좌표 조회는 최대 약 5초 간격을 유지하며, 카메라 표시는 받은 좌표와 최신 GPS·방향 센서로 화면 프레임에 맞춰 갱신합니다. GPS가 오래되거나 부정확할 때, 방향이 3초 이상 갱신되지 않을 때, 서버 조회 실패·오프라인일 때는 보물 표시와 획득을 중지합니다.
- 화면을 닫거나 획득한 뒤, 다른 사람이 먼저 찾거나 게임이 중지된 경우, 브라우저가 배경으로 전환될 때 관련 감시와 카메라 스트림을 정리합니다. 배경에서 돌아오면 다시 켜기 버튼으로 재개합니다.
- 획득 직전에 활성 영상 트랙, 트랙의 사용 가능 상태, 재생 상태, 실제 영상 크기, 현재 화면의 표시 여부를 다시 검사합니다. 지도·미리보기의 직접 획득 경로는 제거했습니다.
- 획득 액션은 `claimCamera`이며 이전 버전의 지도용 `claim` 요청은 서버에서 업데이트 안내와 함께 거부합니다. 웹 카메라 상태는 클라이언트에서 검사하고 서버는 인증·GPS·게임 규칙을 검증합니다. 카메라 하드웨어 작동을 서버에 증명하는 기능은 아니며 사진·영상은 전송하지 않습니다.

## 정확도와 지원 범위

현재 구현은 위치 기반 AR이며, 카메라로 바닥을 인식하거나 물체 뒤에 보물을 가리는 공간 추적 기능은 포함하지 않습니다. 영상은 저장·전송하지 않습니다.

GPS의 수 m 이상 오차, 자기장 간섭, 기기마다 다른 카메라 화각의 영향을 받습니다. 카메라의 긴 변 화각은 약 70°, 카메라 높이는 약 1.3m와 평지로 가정합니다. 경사·실내·높이 차이가 큰 곳에서 정확한 바닥 고정을 보장하지 않습니다. 후면 카메라와 북쪽 기준 방향 센서가 제공되는 HTTPS 휴대폰 브라우저를 사용합니다. 지원하지 않는 기기에는 지도 탐색을 제공합니다.

## 검증

- 단위 테스트: 카메라 회전·기울기·이동·화면 밖·뒤쪽·가로 회전·북쪽 경계 처리, Android/Safari 센서 값과 상대 방향 거부, AR 좌표 접근 범위와 GPS 검증.
- Firebase 에뮬레이터: 실제 callable에서 인증 없는 AR 조회 거부, 가까운 선택 목표만 좌표 제공, 원거리 좌표 미제공, 꽝 비공개, 공개 지도 좌표 비공개, 조회 전후 상태 동일.
- 브라우저: 390px 모바일 화면에서 가상 GPS·방향 센서와 명시적인 테스트 영상을 사용했습니다. 회전·이동에 따른 표시 변화, 부정확한 GPS와 원거리 획득 차단, 근거리 복구, 센서 권한 거부, 배경 전환 후 재시작, 보물 터치로 100점 획득과 카메라·GPS·방향 감시 해제를 확인했습니다.
- 실제 휴대폰의 카메라·나침반 하드웨어와 야외 좌표 오차는 이번 자동 검증에 포함되지 않았습니다. 현장에서 iPhone Safari와 Android Chrome으로 권한 요청, 나침반 보정, 보물을 향한 화면 방향, 세로·가로 회전, 실제 위치에서의 표시 오차를 확인해야 합니다.
