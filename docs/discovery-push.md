# 보물 발견 전체 푸시

서버에서 보물 발견이 확정되면 발견자 본인·참가자·추진위원회를 포함한 현재 전체 인원의 등록 기기로 푸시를 발송합니다. 팀 구분 없이 전송하며, 앱의 기존 푸시 권한과 구독을 사용합니다.

- 금액 보물: `보물 발견!` / `Dave가 5,000원 보물을 발견했어요!`
- 꽝: `앗, 꽝 발견!` / `Dave가 꽝을 발견했어요. 잠깐 쉬고 다시 도전해요!`
- 응원: 제목은 `응원을 발견했어요!`이며, 본문은 아래 9개 중 같은 확률로 무작위 선택합니다. `{name}`에는 서버에서 확인한 실제 발견자 이름을 넣습니다.
- 금액 미지정 보물은 기존 포인트를 표시하고 금액을 임의로 추측하지 않습니다.
- 푸시를 누르면 보물찾기 화면으로 이동합니다. 기존 공지는 계속 소식 화면으로 이동합니다. 앱을 보고 있을 때의 토스트에도 발견자와 금액을 표시합니다.

### 응원 본문

1. `{name}가 응원 보물을 발견했습니다! 마주치면 엄지 척을 날려주세요!`
2. `{name}가 응원을 획득했습니다! 만나면 하이파이브를 요청하세요!`
3. `응원 보물 발견자 {name}! 마주치면 경례로 예우해주세요!`
4. `{name}가 희귀 보물을 찾았습니다! 만나면 축하의 한마디를 건네주세요!`
5. `{name}의 응원 게이지가 충전되었습니다! 마주치면 축하 댄스를 선물해주세요!`
6. `{name}가 행운의 응원을 발견했습니다! 만나면 행운을 나눠달라고 해보세요!`
7. `응원 보물을 획득한 {name}! 만나면 응원 한 스푼을 보태주세요!`
8. `{name}가 응원을 발견했습니다! 마주치면 ‘당신이 보물입니다!’라고 외쳐주세요!`
9. `전설의 응원 보물 발견자 {name}! 마주치면 과장되게 존경을 표해주세요!`

발견이 확정될 때 한 번 선택해 푸시 작업에 저장합니다. 같은 발견의 모든 수신 기기는 같은 문구를 받으며, 전송 재시도에도 저장된 문구를 유지합니다. 서로 다른 발견에서는 같은 문구가 연속으로 선택될 수 있습니다.

## 발송 흐름

`workshopAction`의 성공한 `claimCamera` 트랜잭션이 발견 결과와 비공개 `treasurePushes/{id}` 문서를 함께 저장합니다. 먼저 획득한 한 명의 결과만 성공하므로 동시 발견·실패한 요청·재요청이 추가 발송 요청을 만들지 않습니다. 발송자와 금액은 클라이언트 문구를 신뢰하지 않고 서버의 확정된 발견 기록에서 구성합니다.

`sendTreasureDiscovery`는 새 요청 문서에 대한 Firestore 트리거입니다. 앱의 획득 응답과 별도로 처리해 푸시 장애가 보물 획득을 취소하거나 지연시키지 않습니다. 과거 발견 기록을 일괄 발송하지 않습니다.

- 중복된 토큰과 같은 기기의 이전 구독을 제거하고, 이미 삭제된 참가자는 제외합니다. 500개 단위로 FCM에 전송합니다.
- 150초 처리 잠금으로 같은 요청의 동시 발송을 막고, 배치별 성공한 토큰의 해시를 기록해 재시도에서 제외합니다.
- 일시적 오류는 최대 5회·발견 후 30분 안에서 재시도합니다. 만료된 토큰은 삭제합니다. 발견 삭제·워크샵 초기화가 확인되면 남은 발송을 취소합니다.
- 동일 발견의 알림 태그를 고정해 재전달 시 같은 시스템 알림을 갱신합니다. FCM 접수 직후 기록 전에 프로세스가 중단되는 구간까지 정확히 한 번의 네트워크 전송을 보장할 수는 없습니다.
- 요청 문서는 클라이언트가 읽거나 작성할 수 없습니다. 상태·시도 횟수·FCM 접수/실패 수·종료 사유를 서버에서 기록합니다. FCM 접수는 실제 휴대폰 표시나 읽음 확인을 의미하지 않습니다.
- 설치된 이전 서비스 워커도 본문과 구분된 알림 태그를 표시할 수 있도록 호환 필드를 함께 보냅니다. 클릭 시 보물찾기 이동과 새 토스트는 앱 업데이트 후 적용됩니다.

## 배포 순서

신규 트리거 `sendTreasureDiscovery`를 먼저 배포한 뒤, 발송 요청을 생성하는 `workshopAction`을 배포합니다. 그다음 GitHub Pages의 서비스 워커와 화면을 배포합니다. 트리거 준비 전 생성되어 알림을 놓치는 요청을 방지하기 위한 순서입니다.

- 에뮬레이터에서는 FCM 전송을 모의 처리해 실제 참가자 기기로 테스트 푸시를 보내지 않습니다. 운영 휴대폰 수신 여부는 실제 발견과 각 기기의 알림 허용 상태에 따릅니다.
