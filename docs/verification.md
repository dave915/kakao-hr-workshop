# 검증 결과

검증일: 2026-09-15 (KST). GitHub Pages와 실제 Firebase 프로젝트 연결을 완료했습니다.

## 자동 검증

- 게임 / 권한 / 입력 검증 18개 통과.
- Firestore Emulator 보안 규칙 테스트 6개 통과.
- Auth + Firestore + Functions Emulator 통합 테스트 7개 통과.
- 운영용·미리보기 프런트엔드 빌드와 Functions TypeScript 빌드 통과.
- 프런트엔드와 Functions의 운영용 의존성 `npm audit --omit=dev`: 알려진 취약점 0개. 개발 도구 의존성에는 moderate 등급 경고가 남아 있으며 실제 앱 번들에 포함되지 않습니다.

Firebase 없이 실행하는 `npm test`는 에뮬레이터 테스트 13개를 건너뜁니다. 해당 13개는 각각 `npm run test:rules`, `npm run test:backend`로 별도 실행해 통과했습니다.

### 검증한 주요 경계

1. 개인 입장 코드를 서버가 검증하고 해당 참가자의 Custom Token으로 인증.
2. 정상 입장 32회가 동일한 네트워크의 로그인 실패 제한을 소모하지 않음.
3. 익명 사용자와 일반 참가자의 관리자 동작 차단.
4. 새 참가자는 항상 member 역할로 생성, superadmin 입력 우회 차단.
5. 슈퍼 어드민만 추가 관리자 지정 가능, dave.h 강등 차단.
6. 초대 링크 재발급 시 이전 코드와 세션 버전 모두 차단.
7. 동시에 같은 보물을 찾을 때 한 사람만 성공하고 점수 중복 지급 없음.
8. 보물 반경 밖 / 오래된 좌표 / 불확실한 위치 / 일시 정지 상태의 발견 차단.
9. 꽝을 찾은 사용자에게만 서버 기준 5분 제한 적용, 제한 종료 후 재개.
10. 참가자의 꽝 종류·초대 문서 열람과 직접 점수·권한 쓰기 차단.
11. 이미 발견한 보물의 수정·삭제 및 발견 후 팀 변경 차단.
12. 자신의 입장 링크를 재발급하다 새 링크를 보기 전에 세션을 잃지 않도록 화면에서 자신의 재발급 차단.

## 브라우저 검증

agent-browser로 확인했습니다.

- 데스크톱 1280px / 1440px, 모바일 390px 화면 렌더링 및 모바일 가로 넘침 없음.
- 홈, 일정, 보물 지도, 참가자 관리 화면 렌더링.
- OpenStreetMap 지도와 보물 위치 표시.
- 보물 선택 → 예시 위치에서 발견 → +100 포인트 결과.
- 관리자 참가자 추가 → 개인 입장 링크 발급 → 해당 링크로 접속하여 tester.a로 인식하고 URL에서 코드 제거.
- `/workshop/` 하위 경로에서 manifest `scope` / `start_url`, 앱 아이콘, service worker 경로 확인.
- service worker가 activated 상태이며 페이지를 제어함.
- 브라우저를 오프라인으로 전환하고 새로고침해 앱 화면 재표시.
- 미리보기와 운영 배포의 환경 설정 분리. Firebase가 없는 운영 빌드에서 사용자·관리자 화면이 열리지 않고 준비 안내만 표시되는 것 확인.

브라우저 스크린샷과 에뮬레이터 실행 로그는 로컬 `artifacts/`에 있습니다. 예시 코드가 포함될 수 있어 Git에서 제외했습니다.
